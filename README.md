# Adaptive Resource Orchestration for SLM Inference (RL vs HPA)

Minimal, working Version 2. 8 Python files total. Follow the phases in order —
each one produces the screenshots/artifacts your dissertation chapters need.

```
workload/        app.py, Dockerfile, load_generator.py    -> the SLM service + traffic
manifests/       deployment.yaml, service.yaml,            -> OpenShift objects
                 route.yaml, hpa.yaml
rl_agent/        env.py, sim_env.py, train.py, evaluate.py -> the RL scaling policy
experiments/     run_hpa_baseline.py, plot_comparison.py   -> data collection + graphs
results/         hpa.csv, rl.csv, comparison.png           -> generated by the above
```

---

## Phase 1 — Deploy the inference server

```bash
# from workload/
oc new-project slm-rl-demo          # or use your existing DO280 project
oc new-build --binary --name=slm-inference -l app=slm-inference
oc start-build slm-inference --from-dir=. --follow

# apply manifests (edit the image line in deployment.yaml first if needed)
oc apply -f ../manifests/deployment.yaml
oc apply -f ../manifests/service.yaml
oc apply -f ../manifests/route.yaml
```

Screenshots: `oc get deployment`, `oc get pods`, `oc get svc`, `oc get route`.

Sanity check the route:
```bash
curl -X POST https://<route-host>/generate -H 'Content-Type: application/json' \
  -d '{"prompt": "Hello", "max_new_tokens": 10}'
```

## Phase 2 — Generate traffic

```bash
cd workload
python load_generator.py --url https://<route-host> --rps 2 --duration 300 --concurrency 3
```

Screenshot the terminal output (it prints running request/latency/error stats).

## Phase 3 — Monitoring (Prometheus only)

Your app already exposes `/metrics` in Prometheus format (`slm_requests_total`,
`slm_request_latency_seconds_bucket`, `slm_requests_in_progress`). In the
OpenShift console, confirm these are scraped via the cluster's user-workload
monitoring, or find your Prometheus/Thanos-Querier route:

```bash
oc get route -n openshift-user-workload-monitoring
# or, for cluster monitoring:
oc get route -n openshift-monitoring thanos-querier
```

Screenshot example queries in the Prometheus/Thanos UI:
- `rate(slm_requests_total[1m])`
- `avg(rate(container_cpu_usage_seconds_total{namespace="slm-rl-demo"}[1m]))`
- `histogram_quantile(0.95, sum(rate(slm_request_latency_seconds_bucket[1m])) by (le))`

## Phase 4 — HPA baseline

```bash
oc apply -f manifests/hpa.yaml

# terminal 1: keep traffic running
cd workload && python load_generator.py --url https://<route-host> --rps 3 --duration 600 --concurrency 4

# terminal 2: collect baseline data
cd experiments
python run_hpa_baseline.py \
  --prometheus-url https://<prometheus-route> \
  --namespace slm-rl-demo \
  --deployment slm-inference \
  --duration 600 --interval 15 \
  --out ../results/hpa.csv
```

Screenshot `oc get hpa -w` while traffic runs, to show replica changes.

## Phase 5 — RL agent

Train fast, locally, against the simulator (no cluster needed, seconds not hours):
```bash
cd rl_agent
python train.py --dry-run --timesteps 20000 --out ppo_slm_scaler.zip
```
Screenshot the training output (episode reward climbing over time).

Then scale down replicas back to baseline and evaluate the trained policy
against the REAL cluster, with traffic still running:
```bash
oc scale deployment/slm-inference --replicas=1
oc delete hpa slm-inference-hpa   # RL agent takes over scaling now

python evaluate.py \
  --model ppo_slm_scaler.zip \
  --prometheus-url https://<prometheus-route> \
  --namespace slm-rl-demo \
  --deployment slm-inference \
  --steps 40 --step-interval 15 \
  --out ../results/rl.csv
```
Screenshot the evaluation output (action/reward per step) and `oc get pods -w`
showing the RL agent scaling replicas.

## Phase 6 — Comparison

```bash
cd experiments
python plot_comparison.py --hpa ../results/hpa.csv --rl ../results/rl.csv --out ../results/comparison.png
```

`results/comparison.png` gives you the latency, CPU, replica-count, and
reward/throughput graphs for Chapter 10.

## Notes

- **Local testing before deploying**: run `python workload/app.py` on your
  machine first (needs `pip install -r workload/requirements.txt`) and hit
  `http://localhost:8080/generate` to confirm the model loads and responds
  before you build the container image.
- **Why simulate for training**: live env.py steps sleep for
  `step_interval_seconds` (default 15s) to let the cluster settle, so 20,000
  live timesteps would take ~3.5 days. Training on `sim_env.py` first and
  evaluating the resulting policy on the real cluster (Phase 5) is what makes
  this feasible in a day or two, while still producing genuine live-cluster
  results for your comparison.
- **Deliberately excluded** (per your scope): Kubeflow, distributed
  training/Horovod, GPU Operator, KServe, Serverless, MinIO, model registry,
  pipelines — none of this is needed for the RL-vs-HPA comparison.
